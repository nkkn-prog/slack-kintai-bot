# Slack勤怠管理アプリ 実装計画書

## Context
Slackの「稼働開始」「稼働終了」メッセージをトリガーに、Google Spreadsheetへ勤怠を自動打刻するGASアプリを新規構築する。プロジェクトディレクトリには要件定義書のみ存在し、コードは一切ない状態。

## 実装フェーズ

### Phase 1: 基盤 (Config.gs, appsscript.json, Main.gs)

#### appsscript.json
- タイムゾーン: `Asia/Tokyo`
- OAuthスコープ:
  - `https://www.googleapis.com/auth/spreadsheets`
  - `https://www.googleapis.com/auth/drive`（SS作成・フォルダ移動）
  - `https://www.googleapis.com/auth/script.external_request`（Slack API通信）
- WebApp: `executeAs: USER_DEPLOYING`, `access: ANYONE_ANONYMOUS`

#### Config.gs
- ScriptProperties経由で取得する設定値:
  - `SLACK_BOT_TOKEN`: Slack Bot Token
  - `MASTER_SPREADSHEET_ID`: マスタスプレッドシートID
  - `FOLDER_ID`: スプレッドシート保存先フォルダID
- 定数:
  - `HEADER_ROW = ['日付', '稼働開始', '稼働終了', '稼働時間', '備考']`
  - `TIMEZONE = 'Asia/Tokyo'`

#### Main.gs (doPost)
1. リクエストボディをJSON parse
2. **URL verification challenge** 応答（Slack Events API初期設定時）
3. bot メッセージ除外（`event.bot_id` または `event.subtype` 存在時）
4. **リトライイベント除外**: `CacheService.getScriptCache()` で `event_id` を60秒TTLで管理し重複処理防止
5. メッセージ完全一致判定: `稼働開始` or `稼働終了`
6. AttendanceService へルーティング
7. `ContentService.createTextOutput('')` で即座に200返却

### Phase 2: スプレッドシート層 (SpreadsheetService.gs)

#### マスタスプレッドシート構成

| A列: userId | B列: displayName | C列: spreadsheetId | D列: alertChannelId |
|---|---|---|---|

#### 主要関数

| 関数名 | 役割 |
|---|---|
| `getOrCreateUserSpreadsheet_(userId, displayName)` | マスタSS検索→なければ新規作成・フォルダ移動・マスタ登録 |
| `getOrCreateMonthlySheet_(spreadsheet, dateJST)` | YYYY-MMシート取得/作成、ヘッダー行追加 |
| `findOpenSession_(sheet)` | 最終行から上方向にC列空欄行を探索、行番号を返却 |
| `recordStart_(sheet, dateJST, timeJST)` | 新行追加: `[日付, 開始時刻, '', '', '']` |
| `recordEnd_(sheet, rowNumber, endTimeJST, startTimeStr)` | C列に終了時刻、D列に稼働時間計算結果を記入 |
| `getAllOpenSessions_()` | 全ユーザーの未終了セッション取得（12hアラート用） |

### Phase 4: 打刻ロジック (AttendanceService.gs)

#### handleWorkStart_(userId, channelId, displayName)
1. スプレッドシート取得/作成
2. 当月シート取得/作成
3. 未終了セッションチェック → **あればエラー応答**（二重開始防止）
4. 開始時刻を記録
5. マスタSSの `alertChannelId` を更新（アラート送信先）
6. 成功メッセージを返却: `:clock9: 稼働開始を記録しました（HH:mm）`
7. **LockService.getScriptLock()** で排他制御

#### handleWorkEnd_(userId, channelId, displayName)
1. スプレッドシート取得（なければエラー）
2. 当月シートで未終了セッション検索
3. **なければ前月シートも検索**（日跨ぎ対応）
4. 見つからなければ **エラー応答**（未開始での終了防止）
5. 終了時刻を記入、稼働時間を計算（Date差分で日跨ぎ対応）
6. 成功メッセージを返却: `:clock5: 稼働終了を記録しました（HH:mm）稼働時間：X時間YY分`

---

### Phase 5: 12時間アラート (AlertService.gs)

#### checkUnclosedSessions()（時間駆動型トリガーから呼出）
1. `getAllOpenSessions_()` で全未終了セッション取得
2. 各セッションの経過時間を計算
3. 12時間超過 かつ E列に `12h_alerted` なし → 通知送信
4. E列に `12h_alerted` を書き込み（重複通知防止）
5. 通知メッセージ: `:rotating_light: 稼働開始から12時間が経過しました。稼働終了の入力を忘れていませんか？`

#### setupTimeDrivenTrigger()（初回1回だけ実行）
- `ScriptApp.newTrigger('checkUnclosedSessions').timeBased().everyHours(1).create()`

## 設計ポイント

### Slackリトライ対策
- Slackは3秒以内に200応答がないとリトライする
- `CacheService.getScriptCache()` で `event_id` をキーに60秒TTL保存
- 2回目以降の同一イベントは即座にリターン

### 排他制御
- `LockService.getScriptLock()` で同一ユーザーへの同時リクエストによるレースコンディション防止

### 日跨ぎ対応
- 稼働終了時に当月シートで未終了行が見つからなければ前月シートも検索
- 稼働時間はDate差分計算（時刻のみの引き算ではない）

### 12時間アラートフラグ
- E列（備考）に `12h_alerted` を書き込むことで1回限りの通知を保証
- 別テーブル/ストア不要でシンプル

### OAuth スコープ
| スコープ | 用途 |
|---|---|
| `spreadsheets` | スプレッドシート読み書き |
| `drive` | 新規スプレッドシート作成・フォルダ移動 |
| `script.external_request` | Slack API呼び出し（UrlFetchApp） |

## 検証方法

1. `clasp push` でデプロイ後、Slack Events API の **URL verification** 成功を確認
2. Slackで「稼働開始」投稿 → スプレッドシートに行追加 & Slack応答メッセージ確認
3. 「稼働終了」投稿 → C列・D列記入 & 稼働時間計算の正確性確認
4. **二重開始エラー**: 未終了状態で再度「稼働開始」→ 警告メッセージ確認
5. **未開始終了エラー**: 開始なしで「稼働終了」→ 警告メッセージ確認
6. **日跨ぎ**: 月末に開始、翌月1日に終了 → 正しく終了記録されるか確認
7. **12時間アラート**: 開始時刻を手動で12h前にバックデートし `checkUnclosedSessions()` 実行 → 通知確認
