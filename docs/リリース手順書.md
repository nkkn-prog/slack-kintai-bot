# Slack勤怠管理アプリ リリース手順書

## 前提条件

- Node.js がインストール済み
- Google アカウントを保有
- Slack ワークスペースの管理者権限（またはアプリ作成権限）

---

## 1. clasp のセットアップ

### 1.1 clasp インストール

```bash
npm install -g @google/clasp
```

### 1.2 Google アカウントでログイン

```bash
clasp login
```

ブラウザが開くので、Google アカウントで認証する。

### 1.3 GAS API を有効化

以下のURLにアクセスし、Google Apps Script API を **オン** にする：

https://script.google.com/home/usersettings

---

## 2. GAS プロジェクトの作成

### 2.1 プロジェクト作成

```bash
cd /path/to/kintai-slack-bot
clasp create --type webapp --title "勤怠管理Bot" --rootDir src
```

実行後、`.clasp.json` に `scriptId` が自動設定される。

### 2.2 コードをプッシュ

```bash
clasp push
```

> `appsscript.json` を上書きするか聞かれたら **Yes** を選択。

---

## 3. Google Spreadsheet の準備

### 3.1 マスタスプレッドシートの作成

1. Google Drive で新規スプレッドシートを作成
2. ファイル名：`勤怠管理_マスタ`
3. 1行目にヘッダーを入力：

| A1 | B1 | C1 | D1 |
|---|---|---|---|
| userId | displayName | spreadsheetId | alertChannelId |

4. スプレッドシートIDをメモする（URLの `/d/` と `/edit` の間の文字列）

### 3.2 保存先フォルダの作成

1. Google Drive に勤怠記録用のフォルダを作成（例：`勤怠記録`）
2. フォルダIDをメモする（フォルダを開いたときのURLの末尾の文字列）

---

## 4. GAS Script Properties の設定

### 4.1 GAS エディタを開く

```bash
clasp open
```

### 4.2 Script Properties を設定

1. 左メニュー **歯車アイコン（プロジェクトの設定）** をクリック
2. 下部の **「スクリプト プロパティ」** セクションで以下を追加：

| プロパティ | 値 |
|---|---|
| `SLACK_BOT_TOKEN` | `xoxb-` で始まるBot Token（手順5で取得） |
| `MASTER_SPREADSHEET_ID` | 手順3.1でメモしたスプレッドシートID |
| `FOLDER_ID` | 手順3.2でメモしたフォルダID |

> `SLACK_BOT_TOKEN` は手順5完了後に設定する。

---

## 5. Slack App の作成・設定

### 5.1 Slack App を作成

1. https://api.slack.com/apps にアクセス
2. **「Create New App」** → **「From scratch」**
3. App Name：`勤怠Bot`（任意）
4. ワークスペースを選択して作成

### 5.2 Bot Token Scopes の設定

1. 左メニュー **「OAuth & Permissions」**
2. **「Scopes」** セクションの **「Bot Token Scopes」** に以下を追加：

| スコープ | 用途 |
|---|---|
| `channels:history` | パブリックチャンネルのメッセージ読み取り |
| `groups:history` | プライベートチャンネルのメッセージ読み取り |
| `chat:write` | 応答メッセージの送信 |
| `im:write` | DM通知の送信（12時間アラート用） |
| `users:read` | ユーザー情報の取得 |

### 5.3 ワークスペースにインストール

1. **「OAuth & Permissions」** ページ上部の **「Install to Workspace」**
2. 権限を確認して **「許可する」**
3. 表示される **Bot User OAuth Token**（`xoxb-...`）をコピー
4. **手順4.2 に戻り、`SLACK_BOT_TOKEN` を設定する**

### 5.4 Event Subscriptions の設定

#### 5.4.1 GAS Web App をデプロイ

先に GAS をデプロイして Request URL を取得する必要がある。

```bash
clasp deploy --description "v1.0.0"
```

または GAS エディタ上で：

1. 右上の **「デプロイ」** → **「新しいデプロイ」**
2. 種類：**ウェブアプリ**
3. 説明：`v1.0.0`
4. 次のユーザーとして実行：**自分**
5. アクセスできるユーザー：**全員**
6. **「デプロイ」** をクリック
7. 表示される **ウェブアプリ URL** をコピー

#### 5.4.2 Slack Event Subscriptions を有効化

1. Slack App 設定画面の左メニュー **「Event Subscriptions」**
2. **「Enable Events」** を **On**
3. **「Request URL」** にデプロイしたウェブアプリURLを貼り付け
4. `Verified` と表示されることを確認（URL verification challenge が成功）

#### 5.4.3 イベントを購読

**「Subscribe to bot events」** セクションで以下を追加：

| イベント名 | 用途 |
|---|---|
| `message.channels` | パブリックチャンネルのメッセージ監視 |
| `message.groups` | プライベートチャンネルのメッセージ監視 |

5. **「Save Changes」** をクリック

> イベント追加後、Slack から **「Reinstall your app」** を求められる場合がある。その場合は **「OAuth & Permissions」** から再インストールする。

---

## 6. 12時間アラートのトリガー設定

### 6.1 GAS エディタで実行

1. `clasp open` でGASエディタを開く
2. `AlertService.gs` を選択
3. 上部のドロップダウンで **`setupTimeDrivenTrigger`** を選択
4. **「実行」** ボタンをクリック
5. 初回実行時に権限承認を求められるので **「許可」** する

確認：左メニュー **「トリガー」** に `checkUnclosedSessions` が1時間ごとで登録されていること。

---

## 7. Bot をチャンネルに追加

勤怠Botが反応するには、チャンネルに参加している必要がある。

1. 対象チャンネルで `/invite @勤怠Bot` を実行
2. または、チャンネル設定 → **「インテグレーション」** → **「アプリを追加する」** から追加

---

## 8. 動作確認

### 8.1 基本フロー

1. Bot が参加しているチャンネルで `稼働開始` と投稿
2. `:clock9: 稼働開始を記録しました（HH:mm）` と応答が返ること
3. Google Drive のフォルダに `勤怠記録_<表示名>` スプレッドシートが作成されていること
4. マスタスプレッドシートにユーザー行が追加されていること
5. `稼働終了` と投稿
6. `:clock5: 稼働終了を記録しました（HH:mm）稼働時間：X時間YY分` と応答が返ること
7. スプレッドシートのC列・D列に値が入っていること

### 8.2 エラーケース

| テスト | 期待結果 |
|---|---|
| 未終了状態で `稼働開始` | `:warning: 前回の稼働が未終了です...` |
| 未開始状態で `稼働終了` | `:warning: 稼働開始の記録がありません...` |
| `稼働開始します`（部分一致）| 反応しない |

### 8.3 12時間アラート確認

1. スプレッドシートの開始時刻を12時間以上前の値に手動変更
2. GAS エディタで `checkUnclosedSessions` を手動実行
3. Slack にアラートメッセージが届くこと
4. E列に `12h_alerted` が書き込まれていること

---

## 9. コード更新時の再デプロイ

```bash
# コードをプッシュ
clasp push

# 新バージョンをデプロイ
clasp deploy --description "v1.x.x"
```

**重要**: GAS の Web App は、デプロイバージョンを更新しないと変更が反映されない。

GAS エディタから更新する場合：

1. **「デプロイ」** → **「デプロイを管理」**
2. 鉛筆アイコンをクリック
3. バージョン：**「新バージョン」**
4. **「デプロイ」**

> Request URL 自体は変わらないため、Slack 側の再設定は不要。

## トラブルシューティング

| 症状 | 確認ポイント |
|---|---|
| Slack で反応しない | Bot がチャンネルに参加しているか確認 |
| `Verified` にならない | GAS が正しくデプロイされているか、`doPost` が `url_verification` を処理しているか確認 |
| スプレッドシートが作成されない | Script Properties の `MASTER_SPREADSHEET_ID` と `FOLDER_ID` が正しいか確認 |
| 権限エラー | GAS エディタで手動実行して権限を承認済みか確認 |
| 二重応答 | GAS のログでイベント重複排除（CacheService）が動作しているか確認 |
